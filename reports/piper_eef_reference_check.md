# Piper EEF 参考点核查

## 结论与范围

当前 `lerobot-human-inloop-record --eef.enable=true` 保存的是 Piper SDK 报告的 J6 末端参考点。
核查的已采数据与 SDK 的 J6 正运动学位置一致，没有包含从该点到夹爪两指夹持中心的额外工具平移。
需要以两指夹持中心进行定位时，应另外确定并应用该点相对于 J6 参考系的变换。

本次依据是当前采集实现、已安装的 `piper_sdk==0.6.2`、官方 TCP 示例和实际数据交叉验证。
未连接实时 CAN，也未读取当前控制器工具配置；该结论不外推到以后变更的固件或工具设置。
J6 参考点的物理位置应结合厂家坐标系图确认，不应直接假定为某个可见法兰表面。

## 采集路径

`src/lerobot/scripts/human_inloop_eef.py` 中的 `PiperEefReader.read()`：

1. 读取 `robot.arm.GetArmEndPoseMsgs().end_pose`。
2. 将 XYZ 从 0.001 mm 转为 mm，将 RX/RY/RZ 从 0.001° 转为度。
3. 保存到 `observation.eef_pose`，没有附加平移或旋转。

安装版本的 `GetArmEndPoseMsgs()` 返回控制器反馈消息，SDK 接收更新函数逐项复制位置和姿态值。
本函数不会根据夹爪开度或是否安装夹爪自动补偿 TCP。
数据字段的 `tcp_offset_applied=false` 仅描述本采集代码没有另加工具变换，
该标记本身不能用于证明控制器内部配置；以下实际数值比对提供了独立证据。

## 官方依据

官方示例：

https://github.com/agilexrobotics/piper_sdk/blob/master/piper_sdk/demo/V2/piper_read_tcp_pose.py

核查时该示例先调用 `GetArmEndPoseMsgs()`，把原始位置打印为 `J6 Pos`，
再通过 `apply_tool_offset()` 计算并打印 `TCP Pos`。
其函数说明明确将 `tool_offset` 定义为 J6 坐标系中的工具中心点坐标。

示例中的 `(0, 0, 0.145)` 是单独输入的 145 mm 工具偏移，不能直接作为本机夹爪的实测偏移。
示例使用的旋转关系为 `R = Rz(RZ) @ Ry(RY) @ Rx(RX)`。

SDK 正运动学的固定连杆尺寸包含 `d6=91 mm`；这是其机械臂模型的一部分，
不能把这个参数当作应额外添加的夹爪 TCP 长度。
`dh_is_offset` 切换的是新旧 DH 参数中的关节角偏置，不是夹爪 TCP 开关。

## 实际数据比对

对象：当前 `datas/demo_init_002`，4 段、2174 帧，具有 `observation.eef_pose`。
该目录内容已不同于早先只有 1 段、967 帧的版本。

逐帧读取从臂 `observation.state` 的前 6 个关节角，转成弧度后调用安装版本的
`C_PiperForwardKinematics(dh_is_offset=1).CalFK(joints)[-1]`，得到基座系中的 J6 位姿。
与同一行保存的 EEF 比较；姿态通过旋转矩阵相对旋转角比较，避免欧拉角等价表示的影响。
两种 DH 模型均进行了检查，新模型明显匹配当前数据。

| 指标 | 全部 2174 帧 | 低运动 1938 帧 |
| --- | ---: | ---: |
| 位置差中位数 | 0.00671 mm | 0.00609 mm |
| 位置差 P95 | 0.06213 mm | 0.00671 mm |
| 位置差最大值 | 5.43356 mm | 0.00875 mm |
| 姿态差中位数 | 0.00160° | 0.00133° |
| 姿态差 P95 | 0.10603° | 0.00179° |
| 姿态差最大值 | 3.88964° | 0.00307° |

“低运动”筛选：当前帧与前后相邻数据行的任一关节变化均小于 0.05°。
这个筛选仅用于降低分别读取关节和末端反馈时的时序差影响，不代表精密静止或精度标定。

低运动帧的 J6 局部坐标位移 `R_J6.T @ (p_EEF - p_J6)`：

- 均值约 `[0.002665, -0.000138, 0.000002] mm`。
- 各轴标准差约 `[0.004186, 0.000524, 0.001330] mm`。

旧 DH 模型 `dh_is_offset=0` 在这些低运动帧上的位置差中位数约 9.94342 mm，
说明选错机械臂模型也能产生系统位置误差，不应将其误认成工具偏移。

示例（episode 0，frame 0）：

```text
保存的 EEF XYZ： [63.713001, 0.750000, 179.796997] mm
关节计算 J6 XYZ：[63.7137,   0.7505,   179.7948  ] mm
```

运动帧较大的差异可能来自不同 CAN 消息、控制器更新和读取时序；
本核查不据此声称反馈严格同步，也不把低运动时的数值一致性当作机械臂绝对定位精度。

## 对后续采集的含义

可以继续保留现有 SDK EEF 原始字段。
若目标是夹爪两指中心，测量或标定 `T_J6_TCP` 后应用：

```text
T_base_TCP = T_base_J6 @ T_J6_TCP
```

固定夹爪的变换也可离线应用于历史 EEF 数据，无需仅为补 TCP 字段重新采集。
本次核查没有修改原始数据或机器人设置。
